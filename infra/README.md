# Tessil infra

Reference configurations for the Ploi-managed Hetzner VPS that runs Tessil.
Files in this tree are deployed *manually* by the operator — they are not
auto-applied by Ploi or by any CI hook. Living in git makes them
reviewable, version-controlled, and reproducible after a server move.

```
infra/
├── geoip/           Weekly MaxMind GeoLite2 MMDB refresh (country + ASN + city)
├── nginx/           Security and routing snippets to include from Ploi vhosts
└── systemd/         Hardening drop-in for the API unit
```

## nginx — security headers, restart tolerances, /d/* robots

The nginx vhosts are auto-generated by Ploi and live at
`/etc/nginx/sites-available/tessil.app.conf` and
`/etc/nginx/sites-available/api.tessil.app.conf`. Don't replace those
wholesale — Ploi may regenerate them. Instead, include the snippets in
this tree.

### One-time install on the VPS

```bash
sudo install -d -m 0755 /etc/nginx/snippets
sudo install -m 0644 nginx/snippets/security-headers.conf  /etc/nginx/snippets/tessil-security-headers.conf
sudo install -m 0644 nginx/snippets/api-tolerances.conf    /etc/nginx/snippets/tessil-api-tolerances.conf
sudo install -m 0644 nginx/snippets/download-route.conf    /etc/nginx/snippets/tessil-download-route.conf
```

### Wire them into the vhosts

Edit `/etc/nginx/sites-available/tessil.app.conf` (frontend):

```nginx
server {
    listen 443 ssl http2;
    server_name tessil.app;
    # ... existing Ploi config (root, ssl_certificate, etc.) ...

    include snippets/tessil-security-headers.conf;
    include snippets/tessil-download-route.conf;   # robots-noindex on /d/*

    # ... rest of existing config ...
    # The default `location / { try_files $uri /index.html; }` already serves
    # /d/* via SPA fallback. No /d-specific location block is needed —
    # download-route.conf adds the X-Robots-Tag conditionally at server scope.
}
```

Edit `/etc/nginx/sites-available/api.tessil.app.conf` (API):

```nginx
server {
    listen 443 ssl http2;
    server_name api.tessil.app;
    # ... existing Ploi config ...

    include snippets/tessil-security-headers.conf;

    location / {
        proxy_pass http://127.0.0.1:3000;   # or whatever PORT= is in API .env
        proxy_http_version 1.1;
        proxy_set_header Host              $host;
        proxy_set_header X-Real-IP         $remote_addr;
        proxy_set_header X-Forwarded-For   $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;

        include snippets/tessil-api-tolerances.conf;
    }
}
```

### Validate and reload

```bash
sudo nginx -t
sudo systemctl reload nginx
```

If `nginx -t` complains, fix the config — do not reload a broken nginx (a
reload with bad config aborts safely, but a restart with bad config doesn't).

### Verify from a client

```bash
curl -sI https://tessil.app/ | grep -iE 'strict-transport|content-type-options|frame-options|coop|corp|permissions-policy'
curl -sI https://tessil.app/d/example | grep -i x-robots-tag
curl -sI https://api.tessil.app/health | grep -iE 'strict-transport|content-type-options'
```

You should see all the security headers on the first call, and
`X-Robots-Tag: noindex, ...` on the `/d/example` call.

## systemd — hardening drop-in for tessil-api

The Ploi-generated unit at `/etc/systemd/system/tessil-api.service` runs the
API as the `ploi` user with no sandboxing. The drop-in at
`systemd/tessil-api.service.d/hardening.conf` adds filesystem isolation,
syscall filtering, and resource ceilings without touching the main unit.

### Install

```bash
sudo install -d -m 0755 /etc/systemd/system/tessil-api.service.d
sudo install -m 0644 systemd/tessil-api.service.d/hardening.conf \
    /etc/systemd/system/tessil-api.service.d/hardening.conf

sudo systemctl daemon-reload
sudo systemctl restart tessil-api
sudo journalctl -u tessil-api -n 50 --no-pager
```

The journal should show the API booting cleanly. If it can't bind a port,
write a temp file, or open a socket, the hardening flags are too strict for
the actual workload — adjust `ReadWritePaths` or
`RestrictAddressFamilies` accordingly and re-apply.

### Score it

```bash
systemd-analyze security tessil-api
```

A score of "3.0 OK" or below is the goal. Default Ploi units score around 9;
this drop-in should bring it under 4.

### Roll back

If the hardening breaks the API:

```bash
sudo rm /etc/systemd/system/tessil-api.service.d/hardening.conf
sudo systemctl daemon-reload
sudo systemctl restart tessil-api
```

You're back to the un-hardened default in under 30 seconds.
